# Yap production stack audit

> Superseded for current setup on November 15, 2026: this audit describes the pinned historical commits below. Current generation defaults to fal Seedance 2.5; Seedance 1.5 is retired, and the retained Runway adapter is unselected. Capability gaps here describe that earlier snapshot. Use [API setup](../api-setup.md) and [creator backend](../creator-backend.md) for current behavior.

Audited on November 14, 2026 against core production commit `b52f273`, then rechecked after pulling main `f866837`. The intervening changes add the poster reference/direction workspace without changing the audited video providers, paid-request gate or production worker. Core source links remain pinned to `b52f273`. This note describes implementation, not verified paid-account access. No private workspace guidance, credentials, or private reference material is included.

## Main finding

Yap already has real provider adapters, durable approvals and spending reservations, generated-clip inspection, and MP4 assembly. Its Deep Agents harness coordinates public research; it does not run the production pipeline as an open-ended video-editing agent. Image generation, audio production, reference-video transcription, and a general editing tool registry are absent from the audited production path.

The implemented path is:

`public research + own facts/photos -> script/scenes -> editable clip plan -> quote -> approval -> explicit provider -> clip inspection -> silent assembly -> MP4 + post caption`.

## How tool calls work today

The real Deep Agents coordinator uses `ChatOpenAI`, `createDeepAgent`, `todoListMiddleware`, a run-local `StateBackend`, and three named specialists. Its enforced sequence is:

1. `source_researcher` calls `collect_public_sources` once; later calls reuse the cached batch.
2. `network_analyst` calls `analyze_observed_network` on that collected dataset.
3. `creative_strategist` calls `build_creative_brief` to save attributed framing artifacts.

The tools are constrained application functions with empty argument schemas: the model cannot freely change scope, browse arbitrary media, invoke production, or approve output. The coordinator can plan/delegate and specialists can read their shared research files. Canonical outputs are written by application tools. The default shared bounds are 24 model calls, 48 tool calls, and 120 seconds. [Tool definitions](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/social-deepagents.ts#L267), [coordinator and specialist setup](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/social-deepagents.ts#L379), [bounds](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/social-deepagents.ts#L196).

Creator research can feed an already collected immutable batch to that harness. Its result is creative framing, not visual inspection of referenced videos. Indexed descriptions are explicitly not transcripts. [Creator integration and limitations](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-research.ts#L690), [reference metadata](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-research.ts#L749).

Production instead follows ordinary application control flow: preparation checkpoints completed script and scene stages; the router builds a typed plan; `CreatorJobs` calls the selected provider, records the provider task, inspects the returned file, invokes frame review, and assembles accepted clips. The LLM is not choosing arbitrary editing tools in a production loop. [Preparation](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-router.ts#L477), [production worker](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-jobs.ts#L398).

## Production strengths worth retaining

- **Reviewable plans:** prompts, camera instructions, lighting, reference photo and timing are editable before cost approval. Version changes invalidate dependent approval. [Plan contract](https://github.com/Emmit3/yap./blob/b52f273/packages/contracts/src/creator.ts#L89), [Director editing](https://github.com/Emmit3/yap./blob/b52f273/apps/web/src/creator/CreatorWorkspace.tsx#L1350).
- **Explicit cost boundaries:** quotes bind the current provider/model, prompts, source identity and duration. Admission reserves the approved ceiling and consumes the quote atomically. The durable app cap defaults to USD 30; it is not an account-wide invoice limit. [Quote construction](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-budget.ts#L194), [approval](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-router.ts#L658).
- **No automatic paid provider switching:** fal versus Runway is explicit; uncertain POST outcomes are not replayed. Provider task identity persists before polling. [Factory](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-video-factory.ts#L28), [fal submission persistence](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-fal-provider.ts#L257).
- **Bounded local work:** one paid production worker and at most three concurrent creator jobs per application instance. Current plan approval is rechecked before paid submission, including after asynchronous image preparation. [Admission](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-jobs.ts#L186), [final fal check](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-fal-provider.ts#L240).
- **Manual recovery:** at most two paid attempts per clip for the same plan; a failed audit requires a fresh quote and explicit approval. Passed clips can be reused after integrity verification. Restart marks interrupted jobs failed rather than buying work again. [Contract limits](https://github.com/Emmit3/yap./blob/b52f273/packages/contracts/src/creator.ts#L109), [reuse and audit](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-jobs.ts#L409), [restart](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-repository.ts#L97).
- **Traceable output:** returned media is copied into application storage, hashes protect downloads, and final decode checks cover the produced MP4. Frame review is explicitly sampled; it does not prove every frame is artifact-free. [Integrity verification](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-jobs.ts#L87), [final decode](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-media.ts#L467).

## Current limits relative to a broader video-production studio

| Capability                           | Current status and consequence                                                                                                                                                                                              | Reuse seam for a proposed extension                                                                                                                                                                                          |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Generated storyboard/keyframe images | No still-image generation adapter or image-generation request in the audited path. Uploaded images and generated-video frame samples are inputs to vision, not generated storyboard assets. Scenes are text and clip plans. | Add a typed image-provider interface, generated-asset provenance and hashes, approved image cost quotes, a visible still-image selection/revision step, then pass the selected image to the existing image-to-video adapter. |
| Production agent tools               | Deep Agents tools only serve research; production tools are not exposed as a model-selectable registry.                                                                                                                     | Wrap existing safe application operations with typed tools such as draft plan, generate approved still, generate approved clip, inspect clip and assemble. Preserve version/cost gates inside each operation.                |
| Multimodel routing                   | Only one globally selected video provider per plan; model/provider contracts are literal enums. Current OpenAI paid requests accept one budget model.                                                                       | Add an explicit capability registry and per-shot/provider pricing, then update quote fingerprints, contracts, UI and tests. Avoid silently treating an alternative provider as a free retry.                                 |
| Rich editing/timeline                | Ordered clips and per-clip durations/prompts are editable; no multitrack composition, arbitrary in/out points, transitions, keyframed transforms or edit-decision-list contract is present.                                 | Introduce a versioned timeline/edit decision model and deterministic preview/render operations over stored assets. Keep generation receipts separate from edit revisions.                                                    |
| Narration, music, sound              | Generated plans require `hasAudio:false`; fal requests `generate_audio:false`; assembly strips audio. No TTS/music adapter or audio track model is implemented.                                                             | Add audio assets, timecoded script/voice settings, separate provider pricing and approval, and FFmpeg audio mixing. Change silent-output validation deliberately.                                                            |
| Subtitles                            | The caption is social-post text. Own-photo output can have designed text overlays; generated-video assembly does not produce a subtitle track or burn-in captions.                                                          | Add timed captions and subtitle export/burn-in as explicit render settings; do not confuse them with the post caption.                                                                                                       |
| Reference-video understanding        | Search supplies attributed links/descriptions; it does not retrieve a verified transcript, inspect the video or derive its actual shot list.                                                                                | Add authorized transcript/caption ingestion and sampled scene analysis with timestamps, keeping reference evidence separate from creator-owned production assets.                                                            |
| Output formats                       | Native generated clips are 720p portrait; assembly emits 1080x1920 at 24 fps. This normalization is not evidence of native 1080p generation or added detail.                                                                | Model provider-specific dimensions, ratio, timing and output guarantees, then support additional formats through approved profiles.                                                                                          |
| Hosted asset library                 | Local JSON/files are authoritative; S3 is an explicit export CLI, not automatic object storage, a browser asset library, or a distributed render queue.                                                                     | Persist object keys/asset provenance, create fresh signed links on demand, then add durable jobs and tenant ownership as separate deployment work.                                                                           |

## Important image-generation integration constraint

Adding an OpenAI image request is more than adding an environment variable. The current paid-request gate permits only OpenAI `/v1/responses` and `/v1/chat/completions`, requires `gpt-6-luna`, and permits only local function tools. An image endpoint or built-in image-generation tool will be rejected. A new adapter therefore also needs an explicit price model, reservation/settlement rules, request-size limits and output validation in this boundary. [Paid-request gate](https://github.com/Emmit3/yap./blob/b52f273/apps/api/src/creator-paid-requests.ts#L110).

A model choice should be made after reviewing the reference studio evidence and current provider documentation. This audit establishes Yap's existing seams; it does not claim Higgsfield, GPT Image, or another provider is already integrated or objectively superior.

## Verification status

The creator backend documents injected HTTP/provider tests and generated FFmpeg fixtures, plus deterministic real-SDK research tests. They verify request construction, state transitions, spend admission, cancellation, media decode/assembly and output validation. They do not establish a funded account's model access, actual production quality, provider latency or reconciled invoices. No live paid generation, credential inspection or source-code change was performed for this audit. [Documented verification boundary](https://github.com/Emmit3/yap./blob/b52f273/docs/creator-backend.md#verified-provider-documentation).
